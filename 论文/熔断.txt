于 Sentinel 的微服务熔断降级机制设计与验证
1. 概念说明
在微服务架构中，熔断与降级常被一并讨论，但侧重点略有不同。熔断（Circuit Breaking） 是一种保护机制：当某个依赖服务出现大量失败、响应过慢或异常比例超过阈值时，调用方会暂时停止继续请求该依赖，避免故障在调用链中扩散，造成线程阻塞、资源耗尽等“雪崩效应”。降级（Degradation / Fallback） 则强调在依赖不可用或主动熔断期间，系统仍能以有限功能或替代策略继续对外提供服务，从而保证核心业务流程可用。

在 Alibaba Sentinel 控制台中，上述能力通常以“熔断规则”进行配置；从实现效果上看，熔断触发后往往伴随降级逻辑执行。因此在本系统中，可将“配置熔断规则 + 编写 Fallback 降级逻辑”视为一套完整的容错方案。

2. 系统背景与接入方式
本系统“校园代拿”平台采用 Spring Cloud 微服务架构，包含网关（Gateway）、认证（Auth）、任务（Task）、审计（Audit）、聊天（Chat）、钱包（Wallet）等多个服务，并通过 Nacos 实现服务注册与发现。为提升系统在高并发与局部故障场景下的稳定性，引入 Sentinel 作为流量治理与容错组件，并部署 Sentinel Dashboard 作为规则配置与运行监控入口。

在代码层面，系统通过 spring-cloud-starter-alibaba-sentinel 接入 Sentinel，并开启 feign.sentinel.enabled，使 OpenFeign 远程调用纳入 Sentinel 资源管理。对于 Servlet 微服务与 Spring Cloud Gateway，分别配置限流/熔断后的统一 JSON 响应，HTTP 状态码为 429，便于前端识别“系统繁忙或依赖暂不可用”。

3. 熔断降级的设计原则
结合业务特点，本系统遵循“核心链路优先、非核心能力可降级”的原则：

核心交易链路（如任务发布、接单、钱包扣款/结算）应尽量避免简单熔断后直接跳过，以免产生资金与状态不一致问题；
辅助能力（如审计日志写入、实时消息推送）允许在依赖服务异常时降级处理，即主业务成功，附加能力失败不影响用户关键操作；
网关层可对下游服务异常进行快速失败，防止大量超时请求拖垮入口服务。
基于上述原则，系统在 campus-common 模块中为 Feign 客户端实现了 Fallback 降级类。例如：审计日志调用失败时仅记录告警并跳过写入；实时推送失败时不影响任务状态变更。该设计与 Sentinel 熔断规则配合，形成“规则触发保护 + 代码兜底降级”的双层容错机制。

4. 典型场景与规则配置
（1）审计日志熔断降级
任务审核、用户管理等操作会向 campus-audit-service 写入操作日志。该能力属于旁路功能，不应因日志服务不可用而阻断主流程。系统在 campus-task-service 等资源上为 Feign 调用
POST:/internal/audit/log
配置 Sentinel 熔断规则，采用异常比例策略（如比例阈值 0.5、最小请求数 5、熔断时长 10 s）。当审计服务不可用或调用异常比例升高时，Sentinel 触发熔断，Fallback 逻辑跳过日志写入，而任务审核、用户审核等主业务仍可正常完成。

（2）实时推送熔断降级
任务状态变化会通过 campus-chat-service 进行 WebSocket/实时通知推送。该能力属于体验增强功能。系统为
POST:/internal/realtime/push
配置类似熔断规则。当聊天服务停止或网络异常时，推送链路被熔断，任务状态更新仍成功，仅表现为用户暂时收不到实时提醒，符合降级设计目标。

5. 验证方法与结果
为验证熔断降级有效性，采用“先登录、后停依赖、再执行主业务”的测试方法，避免因管理后台部分页面依赖审计服务而导致误判。具体步骤如下：

保持用户已登录并具备管理员权限；
在 Sentinel Dashboard 的“簇点链路”中确认目标 Feign 资源已出现；
配置并启用对应熔断规则；
停止依赖服务（如 campus-audit-service 或 campus-chat-service）；
再次执行会触发远程调用的主业务操作（如任务审核、状态变更）。
实验结果表明：在依赖服务不可用时，系统未出现长时间阻塞或级联失败；主业务接口返回成功，服务日志中出现“审计日志/实时推送不可用，已跳过”等降级提示，说明熔断与 Fallback 协同生效。该结果验证了本系统在非核心依赖故障条件下仍具备较好的业务连续性与故障隔离能力。

6. 小结
综上所述，Sentinel 熔断机制用于在依赖异常时快速切断无效调用，降级机制用于在熔断或调用失败时提供可接受的替代行为。二者结合可有效提升微服务系统的鲁棒性。本系统已将该机制落地于审计日志与实时推送等非核心链路，并通过实际停服测试验证了“依赖服务挂掉，核心功能仍可用”的设计目标，为后续扩展网关路由熔断、登录链路保护等能力奠定了基础。
