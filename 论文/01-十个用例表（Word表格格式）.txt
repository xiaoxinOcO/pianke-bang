【使用说明】
1. 全选某个用例表区域 → 复制 → 粘贴到 Word。
2. 选中粘贴内容 → 「插入」→「表格」→「文本转换成表格」→ 分隔符选「制表符」→ 列数 2。
3. 或直接在 Word 中「插入表格」2 列，逐行粘贴。

用例表 UC_001  用户注册
================================================================================
用例编号	UC_001
用例名称	用户注册
参与者	未注册用户（准发布者/准接单员）
优先级	高
描述	新用户通过手机号与短信验证码完成账号注册，注册成功后自动登录并进入任务大厅。
前置条件	（1）用户未登录；（2）手机号尚未被注册；（3）短信服务可用或处于开发模拟模式。
基本流程	1. 用户打开系统注册页面。
2. 用户输入手机号，点击「获取验证码」。
3. 系统校验手机号格式与发送频率，向该号码发送 6 位验证码并记录有效期。
4. 用户填写验证码、用户名、登录密码及确认密码。
5. 系统校验验证码正确性、用户名唯一性及密码强度。
6. 系统创建 user_account 记录，初始化信誉分为 80，生成 JWT 令牌。
7. 系统提示注册成功，跳转至任务大厅页面。
异常流程	E1：手机号已注册 → 提示「该手机号已注册，请直接登录」。
E2：验证码错误或过期 → 提示重新获取或重新输入。
E3：用户名已被占用 → 提示更换用户名。
E4：短信发送失败 → 提示稍后重试，记录失败日志。
E5：两次密码不一致 → 前端表单校验拦截。
说明	开发环境下 app.aliyun.dypns.enabled=false 时可返回模拟验证码；生产环境需配置阿里云 AccessKey。

用例表 UC_002  用户登录
================================================================================
用例编号	UC_002
用例名称	用户登录
参与者	已注册用户
优先级	高
描述	已注册用户通过用户名密码或短信验证码方式登录系统，获取访问令牌并进入业务页面。
前置条件	（1）用户账号已注册且 enabled=true；（2）账号未被管理员禁用。
基本流程	【密码登录】
1. 用户在登录页选择密码登录方式。
2. 输入用户名与密码，点击登录。
3. 系统校验凭证，生成 JWT 并写入 activeSessionId（单点登录控制）。
4. 返回 token 与用户信息，前端保存令牌并跳转任务大厅。
【短信登录】
5. 用户输入手机号并获取验证码。
6. 系统校验验证码，若该手机号绑定多个账号则返回候选列表。
7. 用户选择目标账号并确认，系统完成登录。
异常流程	E1：用户名或密码错误 → 提示登录失败，不泄露具体字段。
E2：账号被禁用 → 提示「账号已被禁用，请联系管理员」。
E3：账号在其他设备登录 → 旧会话收到「已在别处登录」提示。
E4：验证码错误 → 提示重新输入。
说明	Token 有效期默认 86400000ms（24 小时）；Gateway 统一校验 Authorization 头。

用例表 UC_003  接单员资格申请
================================================================================
用例编号	UC_003
用例名称	接单员资格申请
参与者	已登录普通用户
优先级	中
描述	用户提交实名信息申请成为认证接单员，经管理员审核通过后方可在大厅接单。
前置条件	（1）用户已登录；（2）当前 rider_approved=false；（3）无待审核申请（rider_application_pending=false）或上次申请已被驳回。
基本流程	1. 用户进入「接单员申请」页面。
2. 填写真实姓名、学号、联系电话及申请理由。
3. 用户提交申请。
4. 系统将 rider_application_pending 置为 true，记录 riderAppliedAt 及申请信息。
5. 系统提示「申请已提交，请等待管理员审核」。
6. 管理员在审核中心通过后，rider_approved=true，用户可接单。
异常流程	E1：必填项为空 → 表单校验提示。
E2：已有待审核申请 → 提示「申请审核中，请勿重复提交」。
E3：已是认证接单员 → 引导至任务大厅。
E4：信誉分过低或账号被封禁 → 提示暂不可申请。
说明	管理员可驳回、通过或撤销接单员资格；撤销后 rider_approved=false。

用例表 UC_004  发布代拿任务
================================================================================
用例编号	UC_004
用例名称	发布代拿任务
参与者	已登录发布者
优先级	高
描述	发布者填写代拿任务信息，系统从钱包预付赏金，任务进入待审核状态。
前置条件	（1）用户已登录；（2）钱包余额 ≥ 任务赏金；（3）必填项完整。
基本流程	1. 用户进入「发布任务」页面。
2. 选择任务类型（EXPRESS/FOOD/PRINT/QUEUE/OTHER）。
3. 填写标题、取件地点、送达地点（可地图选点并记录经纬度）、赏金、联系方式、描述。
4. 可选上传图片、设置配送时间窗口与最晚送达时间。
5. 用户点击提交。
6. 系统校验表单，从发布者钱包扣减赏金（bountyPrepaid=true），写入 delivery_task，状态为 PENDING_REVIEW。
7. 系统记录审计日志，推送 TASK_STATUS 实时事件。
8. 若开启 AI 自动审核，异步触发内容审核；否则等待人工审核。
9. 页面提示「发布成功，等待审核」。
异常流程	E1：钱包余额不足 → 提示充值或降低赏金。
E2：赏金低于系统最低限额 → 表单校验拦截。
E3：必填项缺失 → 前端/后端校验提示。
E4：钱包扣款失败 → 回滚，提示稍后重试。
说明	审核通过后状态变为 OPEN，方可在任务大厅被接单；驳回后发布者可修改重提。

用例表 UC_005  浏览与搜索任务大厅
================================================================================
用例编号	UC_005
用例名称	浏览与搜索任务大厅
参与者	已登录用户（含发布者与接单员）
优先级	高
描述	用户在任务大厅分页浏览待接单任务，可按状态、类型、关键词筛选；支持 Elasticsearch 全文搜索。
前置条件	（1）用户已登录或可游客浏览（视实现而定，本项目需登录后操作接单）；（2）task-service 与 gateway 正常运行。
基本流程	1. 用户进入任务大厅（HallView）。
2. 系统默认加载 status=OPEN 的任务列表，分页展示。
3. 用户可按任务类型、状态筛选，或输入关键词搜索。
4. 若 app.elasticsearch.enabled=true，关键词请求走 ES 索引；否则走 MySQL 模糊查询。
5. 用户点击任务卡片查看详情（取送地点、赏金、发布者、时间要求等）。
6. 大厅顶部展示已发布公告（notice.published=true）。
7. 地图组件（Leaflet）可展示取送点位置。
异常流程	E1：无匹配任务 → 显示空列表提示。
E2：ES 不可用 → 降级为数据库查询，不影响列表展示。
E3：网络超时 → 提示刷新重试。
说明	接口 GET /api/tasks?status=&taskType=&keyword=&page=&size=；经 Gateway 8080 转发。

用例表 UC_006  接单员接单
================================================================================
用例编号	UC_006
用例名称	接单员接单
参与者	已认证接单员
优先级	高
描述	认证接单员在任务大厅接取 OPEN 状态任务，系统更新任务状态并建立双方沟通渠道。
前置条件	（1）用户已登录且 rider_approved=true；（2）任务 status=OPEN；（3）接单员非任务发布者；（4）信誉分未低于限制且未在 blockedUntil 封禁期内。
基本流程	1. 接单员在任务详情页点击「接单」。
2. 系统校验接单员资格与任务状态。
3. 系统将任务 status 更新为 CLAIMED，记录 claimerName。
4. 系统写入审计日志，向发布者推送 TASK_STATUS 实时通知。
5. 接单员可在「我的任务」查看进行中的任务，并可进入聊天联系发布者。
6. 页面提示「接单成功」。
异常流程	E1：非认证接单员 → 引导至接单员申请页。
E2：任务已被他人接取 → 提示「手慢了，任务已被接走」。
E3：发布者尝试接自己的任务 → 业务规则拦截。
E4：信誉分过低 → 提示「信誉分不足，暂不可接单」。
E5：任务非 OPEN 状态 → 提示状态已变更，刷新列表。
说明	接口 POST /api/tasks/{id}/claim；并发接单以数据库乐观/事务控制为准。

用例表 UC_007  任务完成与确认结算
================================================================================
用例编号	UC_007
用例名称	任务完成与确认结算
参与者	接单员、发布者
优先级	高
描述	接单员标记配送完成，发布者确认后任务完结，赏金结算至接单员钱包。
前置条件	（1）任务 status=CLAIMED；（2）操作者为接单员（完成）或发布者（确认）。
基本流程	【接单员完成】
1. 接单员在「我的接单」中点击「标记完成」。
2. 系统将 status 更新为 PENDING_CONFIRMATION，推送通知给发布者。
【发布者确认】
3. 发布者在「我发布的任务」中查看待确认任务。
4. 发布者点击「确认完成」；或超过 pending-confirm-auto-minutes（默认 30 分钟）系统自动确认。
5. 系统将 status 更新为 COMPLETED。
6. 钱包服务将预付赏金转入接单员账户，写入 wallet_transaction（类型 TASK_INCOME 等）。
7. 发布者可对接单员进行 1~5 星评分与文字评价。
8. 推送 TASK_STATUS 事件，双方可在个人中心查看完结记录。
异常流程	E1：非接单员尝试标记完成 → 权限拒绝。
E2：非发布者尝试确认 → 权限拒绝。
E3：任务已超时 OVERDUE → 走超时驳回/申诉流程，非正常完结。
E4：钱包结算失败 → 任务状态回滚或进入异常处理，记录日志。
说明	发布者亦可在待确认阶段发起争议/取消（视业务规则）；评价字段 claimerRating、claimerRatingComment。

用例表 UC_008  钱包提现申请
================================================================================
用例编号	UC_008
用例名称	钱包提现申请
参与者	已登录用户（通常为接单员）
优先级	中
描述	用户将平台钱包内可用余额申请提现至银行卡/支付宝账户，等待管理员审核打款。
前置条件	（1）用户已登录；（2）wallet_account.balance 大于最低提现额；（3）无冲突的待审核提现单。
基本流程	1. 用户进入「我的钱包」页面，查看余额与流水。
2. 用户点击「申请提现」，填写提现金额、收款户名、账号及备注。
3. 系统校验金额 ≤ 可用余额，创建 wallet_withdraw_request，status=PENDING。
4. 系统冻结对应金额（withdrawingAmount 增加，balance 减少）。
5. 写入 wallet_transaction 流水。
6. 提示「提现申请已提交，等待审核」。
7. 管理员在后台「提现审核」模块审批；通过后 status=APPROVED，累计 totalWithdrawn；驳回则退回余额。
异常流程	E1：提现金额超过余额 → 提示余额不足。
E2：收款信息不完整 → 表单校验。
E3：存在未处理提现单 → 提示等待上一笔处理完成。
E4：管理员驳回 → 退回余额，用户可查看 auditRemark。
说明	本项目为演示级虚拟钱包，无真实第三方支付回调；接口 POST /api/wallet/withdraw。

用例表 UC_009  管理员审核任务
================================================================================
用例编号	UC_009
用例名称	管理员审核任务
参与者	平台管理员
优先级	高
描述	管理员在审核中心对 PENDING_REVIEW 任务进行人工通过或驳回；可与 AI 自动审核配合。
前置条件	（1）操作者用户名在 app.admin.usernames 白名单内；（2）任务 status=PENDING_REVIEW。
基本流程	1. 管理员登录并进入管理后台「审核中心-任务审核」。
2. 系统列出待审核任务，展示标题、类型、赏金、描述、图片等。
3. 管理员查看任务详情，判断是否违规或信息不实。
4a. 点击「通过」→ 系统调用 POST /api/tasks/{id}/approve，status 变为 OPEN，任务进入大厅。
4b. 点击「驳回」→ 填写 adminRejectRemark，status 变为 REJECTED，赏金退还发布者钱包。
5. 系统写入 admin_operation_log，推送 TASK_STATUS 通知发布者。
6. 若启用 AI 自动审核，管理员可在「AI 模型」模块配置 Ollama 参数与自动审核开关。
异常流程	E1：非管理员访问 → 返回 403 或业务异常「仅管理员可执行」。
E2：任务已被其他管理员处理 → 提示状态已变更。
E3：AI 服务不可用 → Feign Fallback 保持待审核，不误驳回。
说明	AI 审核接口 POST /internal/ai/audit-task；Sentinel 可对慢调用配置熔断。

用例表 UC_010  用户间私信聊天
================================================================================
用例编号	UC_010
用例名称	用户间私信聊天
参与者	已登录用户（发布者与接单员等）
优先级	中
描述	任务相关用户通过私信沟通取送细节；新消息经 WebSocket 实时推送。
前置条件	（1）双方均已登录；（2）chat-service 与 WebSocket 通道可用。
基本流程	1. 用户进入「消息/聊天」页面，查看联系人列表（含未读数）。
2. 用户选择目标联系人，系统加载历史消息 GET /api/chat/history?targetUser=xxx。
3. 用户输入文字内容，点击发送 POST /api/chat/send。
4. 系统持久化 chat_message，并向接收方推送 CHAT_MESSAGE 实时事件。
5. 接收方若正在聊天页则刷新消息；否则未读数 +1 并弹出 Toast 提醒。
6. 用户可点击 Toast 快速跳转至对应会话。
异常流程	E1：消息内容为空 → 前端拦截。
E2：WebSocket 断开 → 自动重连；离线期间消息仍可通过历史接口拉取。
E3：chat-service 熔断 → 消息发送失败提示，不影响任务主流程。
E4：向不存在用户发消息 → 后端校验失败。
说明	WebSocket 地址 ws://host:8080/ws，协议 STOMP + SockJS；Gateway 路由 lb:ws://campus-chat-service。
